# Localization in Auger

Auger's user-facing strings live in Xcode String Catalogs inside this repository.
This document covers where strings live, how Swift code should load them, and what CI enforces.

## Where strings live

- `iosApp/iosApp/Localizable.xcstrings` holds all in-app copy.
  Every entry uses `extractionState: manual`, and Xcode turns each key into a `LocalizedStringResource` symbol: `common.cancel` becomes `.commonCancel`, and `home.section.recentlyAddedIn` becomes `.homeSectionRecentlyAddedIn(_:)`.
  An underscore starts a new word (`catalog.extra.behind_the_scenes` -> `.catalogExtraBehindTheScenes`), and so does a letter after a digit (`watchParty.seat.a11yHost` -> `.watchPartySeatA11YHost`).
- Arguments are positional and unlabeled, in the key's placeholder order, except the labelled count described under **Counts** below.
- Both `Auger` and `AugerTopShelf` include `Localizable.xcstrings` in `iosApp/project.yml`.
- `iosApp/InfoPlist/tvOS/InfoPlist.xcstrings` holds tvOS permission prompt text.
  Keep its English entries identical to `iosApp/iosApp/tvOS-Info.plist`.
- A language ships when `Localizable.xcstrings` provides translations for it.
  The language picker and device-language matching read the bundle's localizations directly.

## Adding or changing a string

1. Add or edit the key in `iosApp/iosApp/Localizable.xcstrings` with a clear `comment` describing where the text appears and what each positional placeholder holds ("1: series name, 2: episode number").
2. Keep `extractionState` set to `"manual"`.
3. Run `python3 scripts/ci/check-catalog-text.py` and `bash scripts/ci/check-string-localized.sh` alongside `xcodebuild test`.

## Call sites

The root view sets `\.locale` and `\.layoutDirection` to the profile's app language, so SwiftUI text switches as soon as the language changes, with no relaunch.

**In a view**, pass the symbol:

```swift
Text(.commonCancel)
Button(.commonCancel, role: .cancel) { dismiss() }
Text(.detailSeasonCount(seasons))
.navigationTitle(Text(.settingsAppLanguageTitle))
```

**From a model or view model**, return `LocalizedStringResource` and let the view render it:

```swift
enum DownloadState {
    case paused, complete
    var label: LocalizedStringResource {
        switch self {
        case .paused: .downloadsStatePaused
        case .complete: .downloadsStateComplete
        }
    }
}

Text(state.label)
```

**When a `String` is needed outside a view** (an accessibility label built in code, Top Shelf, an `errorDescription`), resolve it through `AppLanguage.string(_:)`:

```swift
collection.title = AppLanguage.string(.homeSectionContinueWatching)
```

`String(localized:)`, `NSLocalizedString` and `Bundle.localizedString(forKey:)` use the process language rather than the in-app language.
`scripts/ci/check-string-localized.sh` blocks them outside `AppLanguage.swift`.

**Non-interface text** (names, numbers, server values, or wire data) stays verbatim via `Text(verbatim:)` or `.verbatim(text)`.
Text that is stored, sent to the server, matched, or compared stays English in every language.
When wire data reuses label helpers, wrap it in `AppLanguage.inEnglish { ... }`.

**Counts.** Apple formats integer placeholders with locale grouping ("1,234").
Use `{count_text}` with `LocaleFormat.integer(n)` for ungrouped integers or identifiers, and `LocaleFormat.groupedCount(n)` for grouped counts ("1,284 movies").
Never use `String(n)` or `"\(n)"` for user-visible numbers.

**When a view needs a `String`**, read `@Environment(\.locale)` and pass it to `AppLanguage.string(_:locale:)` so the view re-renders on language changes.

**Plurals** use ICU plural rules in the string catalog, never string concatenation in code.

**Server-authored text** (section titles, problem details, settings-manifest labels) goes through `AppLanguage.serverText` (`section.displayTitle(in: locale)`, `problem.localized(text)`, `SettingPresentationMetadata.unsetLabel(for:fallback:)`).

**Names and titles joined outside the catalog** go through `AppLanguage.isolated(_:)` so punctuation stays intact in right-to-left languages.

## Numbers, dates and names

Format with the app's language rather than `Locale.current`:

- In a view, `Text(date, format: ...)` and `Text(n, format: ...)` inherit `\.locale`.
- Outside a view, use `Shared/LocaleFormat.swift` (`integer`, `decimal`, `percent`, `rate`, `clock`, `duration`, `bytes`, `ordinal`, `languageName`, `dateFormatter`) with an explicit `locale:`.
- Wire and storage values stay POSIX.

## Right to left

The root view sets `\.layoutDirection`.

- Use semantic SF Symbols (`chevron.forward`/`chevron.backward`, `arrow.forward`/`arrow.backward`, `arrow.up.forward`).
- Keep media timelines and transport rows left-to-right with `.mediaLayoutDirection()`.
- Map Siri Remote physical directions through `MoveCommandDirection.inLayout(layoutDirection)` where left/right is layout-dependent.

## Converted code stays converted

`scripts/ci/catalog-text-paths.txt` lists paths whose UI text must come from the string catalog.
`scripts/ci/check-catalog-text.py` checks those paths for literal English UI strings.
Lines that intentionally keep a literal (brand name, technical token such as `"HDR"`, or wire/storage value) end with `// i18n-ignore: <reason>`.

## Tests

Tests render English from the real catalog.
Do not assert translated non-English strings; to test lookup rules, replace `AppLanguage.catalogLookup` with a small table as `Tests/ServerTextTests.swift` does.
